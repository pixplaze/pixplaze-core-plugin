# Pixplaze Core Plugin

Spigot-плагин Minecraft-сервера Pixplaze. Поднимает на сервере HTTP/WebSocket API (состояние сервера,
игроки, плагины, консоль, чат) и связывает сервер с [web-api](../pixplaze-web-api): регистрация через device-flow,
heartbeat, проверка входящих токенов. Типы контракта с web-api — в библиотеке
[`pixplaze-ext-api`](../pixplaze-ext-api), см. раздел [«Библиотека ext-api»](#библиотека-ext-api).

## Стек

- **Java 17**, **Spigot API** (`api-version: 1.18`)
- **Javalin 6** (HTTP и WebSocket, внутри Jetty), Gson (из Spigot)
- `pixplaze-ext-api` — DTO и интерфейсы контракта с web-api
- Сборка — Maven + `maven-shade-plugin`: зависимости вшиваются в jar плагина

## Требования

- **Машина сборки:** JDK 17+ и Maven 3. В репозитории нет `mvnw`: нужен системный `mvn` или Maven из IDE.
- **Сервер:** Spigot или его форк (Paper и т. п.) 1.18+ на Java 17+.

> Плагин собирается против `spigot-api 1.21.4`, а заявлена поддержка с 1.18. Компилятор не мешает
> вызвать метод, которого нет в 1.18. На старом сервере такой вызов упадёт с `NoSuchMethodError`,
> поэтому новый Bukkit API сверяйте с javadoc 1.18.

## 1. Установить pixplaze-ext-api

Зависимость берётся из локального `~/.m2`, поэтому установите её до первой сборки и после каждого
изменения библиотеки:

```shell
cd ../pixplaze-ext-api && ./mvnw -DskipTests install && cd -
```

Версии библиотеки и плагина совпадают (сейчас `1.0.2`). Изменили контракт — поднимите версию в обоих `pom.xml`.

## 2. Сборка

```shell
mvn -DskipTests package
```

Куда попадёт jar, решает переменная окружения `PIXPLAZE_PLUGIN_DIR`:

| `PIXPLAZE_PLUGIN_DIR`       | Результат                                                           |
|-----------------------------|---------------------------------------------------------------------|
| задана (папка `plugins`)    | `$PIXPLAZE_PLUGIN_DIR/pixplaze-core-plugin-<версия>.jar` — сразу на тестовый сервер |
| не задана                   | `target/pixplaze-core-plugin-<версия>.jar`                          |

В обоих случаях это jar со вшитыми зависимостями (~4,5 МБ). `original-*.jar` в `target/` — без
зависимостей, на сервер его класть нельзя.

Тесты (JUnit 5):

```shell
mvn test
```

## 3. Установка на сервер

1. Положить jar в `plugins/` и запустить сервер — создастся `plugins/PixplazeCorePlugin/config.yml`.
2. Заполнить конфиг (ниже) и перезапустить сервер.
3. Для иконки в листинге Pixplaze нужен `server-icon.png` в корне сервера.

## Конфигурация

`plugins/PixplazeCorePlugin/config.yml`:

| Ключ               | По умолчанию  | Назначение                                                                 |
|--------------------|---------------|----------------------------------------------------------------------------|
| `http-listen-port` | `25566`       | порт HTTP/WS API плагина; он же уходит в web-api как адрес типа `API`      |
| `server-host`      | `""`          | публичный хост, по которому заходят игроки (`play.example.net`)           |
| `access-token`     | `YourToken`   | устарел; уйдёт с device-авторизацией                                       |

**`server-host`.** Если ключ пуст, хост определяется по адресам, с которыми подключаются игроки
(побеждает самый частый домен). Значит, сразу после старта хоста нет, пока не зайдёт первый игрок.
За Velocity и за прокси без IP-forwarding автоопределение не работает, поэтому хост нужно задать явно.
Без хоста плагин не сообщает web-api свои адреса.

## HTTP и WebSocket API

| Метод | Путь                        | Что отдаёт                                      |
|-------|-----------------------------|-------------------------------------------------|
| GET   | `/server`                   | `MinecraftServerInfo`: адреса, motd, иконка, ядро, состояние, плагины |
| GET   | `/server/state`             | `MinecraftServerStateInfo` со списками игроков  |
| GET   | `/server/plugins/installed` | `MinecraftPluginInfo[]` — все jar в `plugins/`  |
| GET   | `/server/plugins/enabled`   | `MinecraftPluginInfo[]` — включённые            |
| GET   | `/server/players?view=`     | игроки: `all` (по умолчанию), `online`, `offline`, `banned`, `whitelisted`, `operators` |
| GET   | `/players`, `/players/{uuid}` | `MinecraftPlayerInfo`                         |
| WS    | `/console`                  | лог сервера и консольные команды (администратор), см. ниже |
| WS    | `/chat`                     | видимый всем чат и команды обычного игрока, см. ниже |

### WebSocket: `/console` и `/chat`

Оба сокета устроены одинаково (`MessageWebSocketController`), различаются источником сообщений и тем,
что принимают от клиента.

**Кадры от плагина.** Сообщение — `MinecraftMessageInfo` из ext-api (`type`, `author`, `authorUuid`,
`text`, `timestamp` в мс):

1. Сразу после подключения — история (до 256 сообщений) **JSON-массивом**. Клиент заменяет ею свой
   список, поэтому при переподключении история не задваивается.
2. Дальше — каждое новое сообщение отдельным кадром, **JSON-объектом**.

Текст сырой: в нём бывают `§`-коды Minecraft и ANSI-последовательности. Оформление (`[Server] …`,
`* Steve …`) — на стороне клиента, автор приходит отдельным полем. Исключение — `CHAT`: в `author`
отображаемое имя с префиксами, в `text` строка целиком, как её видят игроки.

**Кадры от клиента** — строка текста; многострочные отклоняются.

| Сокет      | Источник (`type`)                                               | Что принимает |
|------------|------------------------------------------------------------------|---------------|
| `/console` | лог сервера через фильтр log4j (`CONSOLE`)                       | любая консольная команда, `/` в начале необязателен |
| `/chat`    | события Bukkit: `CHAT`, `JOIN`, `QUIT`, `DEATH`, `BROADCAST`, `SAY`, `ME`; веб-сообщения `WEB` | текст — в чат всем игрокам с префиксом `[Web]`; команды `/msg` (`/tell`, `/w`), `/me`, `/list`, `/help`; не больше 256 символов |

- Команды выполняются в главном потоке от имени консоли, перед запуском — `ServerCommandEvent`, как для
  команды, набранной в консоли сервера: другие плагины её видят и могут отменить.
- Ответ, который видит только отправитель (`/list`, `/help`, неизвестная команда, слишком длинное
  сообщение), приходит ему одному с типом `REPLY` и в историю не попадает.
- В `/chat` попадает только то, что видят **все** игроки: отменённые события и сообщения с урезанным
  списком получателей (локальный чат, рассылка по праву) пропускаются. Личные сообщения, `/tellraw`
  и сообщения, которые плагины шлют игрокам по одному, не ловятся — у них нет событий. Сообщения
  плагинов чата, которые отменяют событие и рассылают сами, тоже не видны.
- Плагин пингует клиента на половине тайм-аута простоя Jetty, поэтому тихий сервер соединение не рвёт.
- Отправка неблокирующая. Очередь клиента ограничена 1000 кадров, запись кадра — 30 с (настройки
  Jetty, `JavalinExchangeServer`). Не уложился — соединение закрывается с кодом `1013`, клиент
  переподключается и получает историю заново.

## Библиотека ext-api

`pixplaze-ext-api` — общий контракт web-api и плагина: DTO, коды OAuth-ошибок и интерфейсы клиента.
Web-api отдаёт и принимает эти типы, плагин их собирает и отправляет. Поэтому поле, переименованное
в одном проекте, ломает другой. Меняйте контракт только в библиотеке и пересобирайте оба проекта.

### Что в ней есть

| Пакет `com.pixplaze.api.ext…` | Содержимое                                                                 |
|-------------------------------|----------------------------------------------------------------------------|
| (корень)                      | интерфейсы: `MinecraftServerApi` (что сервер знает о себе), `PixplazeWebApi`, `DeviceAuthorization`, `DeviceAuthorizationClient`, `PendingAuthorization`; `OAuthException` |
| `data.server`                 | `MinecraftServerInfo`, `MinecraftServerStateInfo`, `MinecraftServerHostInfo`, `MinecraftServerCoreInfo` |
| `data.player`                 | `MinecraftPlayerInfo`, `MinecraftPlayerListInfo`                           |
| `data.plugin`                 | `MinecraftPluginInfo`                                                      |
| `data.auth`                   | детали device-flow (`MinecraftServerAuthorizationDetails`, `MinecraftPlayerAuthorizationDetails`), пары токенов, `Authority` с именами JWT-claim'ов, `MinecraftServerTargets` (`aud` = `mc:server:<id>`) |
| `data.oauth`                  | `DeviceAuthorizationResponse`, `OAuthErrorResponse`, `OAuthError`         |
| `data.message`                | `MinecraftMessageInfo` — сообщение сокетов `/console` и `/chat`           |

### Как плагин её использует

- **`MinecraftServerApi`** реализует `MinecraftServerDao`. Его же данные отдают REST-маршруты выше.
- **`PixplazeWebApi`** и device-flow клиенты — **только интерфейсы**. HTTP-реализацию пишет плагин.
  Готов в библиотеке только цикл опроса `PendingAuthorization.await()` (с `interval` и `slow_down`).
- Heartbeat собирается фабрикой `MinecraftServerInfo.heartbeat(...)`
  (`MinecraftServerDao.getHeartbeatInfo()`), а не билдером.

Сам протокол — эндпоинты, порядок регистрации, refresh, heartbeat, проверка токенов — описан в
[`authorization-consumer-guide.md`](../pixplaze-web-api/authorization-consumer-guide.md).
Если гайд расходится с кодом библиотеки, верен код.

### Правила контракта

Полностью они описаны в `data/package-info.java` библиотеки. Важное для плагина:

- **`null` значит «не входит в это представление»**, а не `false`, `0` или «пусто». Одна запись
  обслуживает несколько представлений (`preview`, `heartbeat`, …). Именованная фабрика заполняет
  только свои поля, остальное получатель игнорирует.
- **Имена:** boolean начинаются с `is` (`isLicense`), ссылка на сервер — `minecraftServerId`, бинарные
  данные — `*Base64`. Длительности в мс, а OAuth `expires_in` и `interval` — в секундах.
- **JSON:** в библиотеке нет JSON-аннотаций. Поля в camelCase, но ответы OAuth-эндпоинтов приходят
  в snake_case (`device_code`, `access_token`, `public_key`). В Gson для них нужен отдельный экземпляр
  с `FieldNamingPolicy.LOWER_CASE_WITH_UNDERSCORES`; общий `JavalinGsonWrapper` трогать нельзя.
- **Совместимость:** новое поле или значение enum совместимо, переименование и удаление — нет.
  Неизвестные поля игнорируются, неизвестный enum читается как `null` (например, `OAuthException.error()`).
- Код библиотеки — Java 17, javadoc на английском.

### Упаковка

Библиотека вшивается в jar плагина **без релокации** (`com.pixplaze.api.ext` как есть). Если на одном
сервере окажутся два плагина с разными версиями ext-api, классы могут конфликтовать. Тогда добавьте
`<relocations>` в конфигурацию `maven-shade-plugin`.

## Эксплуатация

- **Логи сокетов:** подключения и отключения (с кодом закрытия) пишутся на уровне `FINEST`, отключённые
  при неудачной отправке клиенты — на `FINE`; по умолчанию сервер их не показывает.
- **Логи:** в лог сервера, через логгер плагина. Новые сообщения пишутся на английском.
- **Перезагрузка:** `onDisable` отцепляет буферы от log4j и событий Bukkit и останавливает HTTP-сервер, но на живом
  сервере `/reload` не проверялся. Для продакшена лучше полный перезапуск.
